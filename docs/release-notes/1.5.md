## 설치 순서

설치 화면의 순서는 설치 스크립트(`packaging/windows/installer.iss`)의 설정에서 나오는 것이다. 자동 시험은 화면 없이 하는 조용한 설치로만 했다.

1. `Band-Heater-Logger-1.5-windows-x64-setup.exe`를 받는다. 받은 파일이 맞는지 보려면 아래 "받은 파일 확인"을 따른다.
2. 파일을 두 번 누른다. 코드 서명을 하지 않은 파일이라 "Windows의 PC 보호" 창(SmartScreen)이 뜬다. `추가 정보`를 누른 뒤 `실행`을 누른다.
3. 설치 대상을 묻는다. "지금 사용자용"(권장)은 관리자 권한 없이 설치한다. "모든 사용자용"은 관리자 권한을 요구한다.
4. 사용권 계약(MIT 라이선스)에 동의한다.
5. 설치 폴더를 고른다. 기본값은 지금 사용자용이면 `C:\Users\<사용자>\AppData\Local\Programs\Band Heater PID Logger`, 모든 사용자용이면 `C:\Program Files\Band Heater PID Logger`다.
6. 바탕화면 아이콘을 만들지 고른다. 기본은 만들지 않음이다.
7. `설치`를 누른다. 끝나면 "프로그램 실행"에 표시한 채로 `마침`을 누르면 바로 켜진다.

설치 화면의 언어는 윈도우 표시 언어를 따른다. 한국어 윈도우면 한국어, 그 밖에는 영어다.

## 처음 실행

1. 프로그램을 먼저 켠다. 포트를 열면 나노가 리셋되기 때문에(아두이노의 정상 동작), 운전 중에 켜면 히터가 꺼진다. 프로그램을 켠 뒤에 운전을 시작한다.
2. 보드를 USB로 연결한다. 프로그램이 포트를 스스로 찾는다. USB 제조사 번호가 FTDI(0403), CH340(1A86), CP210x(10C4), 아두이노(2341, 2A03), Prolific(067B)인 포트를 먼저 고르고, 속도는 115200이다. 포트가 여러 개면 왼쪽 패널의 포트 목록에서 직접 고른다.
3. 연결되면 보드가 1초마다 보내는 값이 그래프와 파일에 쌓인다. 프로그램은 3초마다 `show`를 보내 상태와 설정을 읽는다. `show`는 EEPROM에 쓰지 않는 명령이다.
4. 보드가 없으면 왼쪽 패널의 `연습 모드`를 누른다. 펌웨어를 PC용으로 그대로 컴파일한 가상 보드가 30배속으로 돈다. 실제 히터는 켜지지 않는다. 가상 보드의 온도 곡선은 임의로 정한 열 모델이라 실제 히터의 값이 아니다.
5. 화면 언어는 툴바에서 한국어와 영어 중에 고른다. 처음에는 한국어다.

창은 1280 × 880으로 열리고 1000 × 700보다 작아지지 않는다. 화면은 이 컴퓨터 안의 주소 `127.0.0.1`의 포트 8765(쓰는 중이면 8784까지 차례로)에서만 열린다. 다른 컴퓨터에서는 접속할 수 없고, 명령을 보내는 요청은 실행할 때마다 새로 만드는 토큰이 있어야 받는다. 프로그램이 켜져 있는 동안은 PC가 절전으로 들어가지 않게 한다. 화면이 꺼지는 것은 막지 않는다.

화면의 기능(툴바, 차트, 통계, 응답, 피팅, 모델, 분석, 온도 프로그램, PC 경보, 안정 판정, 기록 목록, 보고서, 설정, 단축키)은 [README의 표](https://github.com/jongsu-king/band-heater-pid#기록-프로그램)에 있다.

## 기록 파일

기록은 문서 폴더의 `밴드히터_기록`에 남는다. 문서 폴더의 위치는 윈도우에 물어서 정하므로 OneDrive로 옮겨져 있으면 그쪽에 생긴다. 왼쪽 패널의 `기록 폴더`를 누르면 탐색기로 열린다. 연습 모드의 기록은 그 안의 `연습` 폴더에 따로 남는다.

실험(기록)마다 파일 네 개가 생긴다. 이름은 `heater_날짜_시각_이름`으로 시작한다.

| 파일 | 내용 |
|---|---|
| `.csv` | 1초마다 한 줄. 열은 `time, elapsed_s, PV_degC, SP_degC, OUT_pct, T1_degC, T2_degC, T3_degC, T4_degC, mode` |
| `_events.txt` | 운전, 정지, 경보, 설정 변경, 보낸 명령, 마커 |
| `_raw.log` | 보드가 보낸 줄 전부, 받은 시각과 함께 |
| `_meta.json` | 실험 이름, 시료, 메모, 채널 이름, 펌웨어 버전, 시작할 때의 PID 설정, 열 설명 |

화면에서 저장하면 같은 이름 머리로 `_stats.tsv`(구간 통계), `_part_*.csv`(구간만), `_graph_*.png`(그림), `_report_*.html`(보고서)이 더 생긴다. 프로그램 단계, 경보 한계, 언어 같은 설정은 기록 폴더의 `설정.json`에 남는다. 값이 한 줄도 없고 마커도 없는 기록은 끝낼 때 지운다.

## 제거, 다시 설치, 새 버전

- 제거: 설정 → 앱 → 설치된 앱에서 `Band Heater PID Logger`를 제거한다. 프로그램 폴더와 바로 가기, 등록 정보가 지워진다. **기록 폴더(`밴드히터_기록`)는 지우지 않는다.**
- 다시 설치: 같은 설치 파일을 다시 실행하면 같은 자리에 덮어 설치한다.
- 새 버전: 새 설치 파일을 실행하면 같은 자리에 덮어 설치하도록 만들었다(이전 버전의 `_internal` 폴더를 먼저 비운다). 이 릴리스가 첫 버전이라 버전을 올리는 설치는 시험하지 못했다.
- 자동 업데이트는 없다. 새 버전은 이 저장소의 릴리스에서 받는다.

## 윈도우용으로 바꾼 것

프로그램 기능은 1.5 그대로다. 윈도우에서 맞게 돌도록 다음을 고쳤다. 맥과 리눅스의 동작은 바뀌지 않았다.

| 부분 | 내용 |
|---|---|
| 가상 보드 (`tools/sim/sim.cpp`) | 윈도우에서는 표준입력 파이프를 `PeekNamedPipe`로 와 있는 만큼만 읽는다. 윈도우의 `Sleep`이 15 ms 단위로 길어질 수 있어서 실제 시간보다 앞선 만큼만 쉬어 배속을 맞춘다 |
| 가상 보드 실행 (`heater_log.py`) | 윈도우에서는 `sim_bin.exe`를 찾고, 검은 콘솔 창이 뜨지 않게 띄운다 |
| 기록 폴더 | 윈도우에서는 문서 폴더를 시스템에 물어 정한다(`SHGetFolderPathW`). OneDrive 등으로 옮겨진 경우를 위한 것이다 |
| 절전 방지 | 맥의 `caffeinate`에 해당하는 것으로 `SetThreadExecutionState`를 쓴다 |
| 두 번 켰을 때 | 윈도우에서는 화면용 서버가 이미 쓰는 포트에 겹쳐 붙을 수 있어서(`SO_REUSEADDR`의 동작이 다름) 그 옵션을 끄고 다음 포트로 넘어가게 했다 |
| 포트 사용 중 안내 | 다른 프로그램이 COM 포트를 쓰고 있을 때 윈도우가 내는 오류(`PermissionError`)도 "다른 프로그램이 사용 중 (아두이노 시리얼 모니터를 닫으세요)"로 보인다 |
| 묶음 (`packaging/heater_app.spec`) | 윈도우는 폴더로 묶고, exe의 파일 속성에 버전을 넣는다. 설치 스크립트가 그 버전을 읽는다 |
| 빌드 (`build_windows.bat`) | 가상 보드 컴파일, PyInstaller, Inno Setup까지 한 번에 한다 |

## 확인한 것과 확인하지 못한 것

확인한 것. 모두 GitHub Actions의 윈도우 러너에서 이 릴리스의 설치 파일을 만든 바로 그 실행 안에서 한 것이다(실행 주소는 "빌드 정보"에 있다).

1. 윈도우에서 컴파일한 가상 보드로 펌웨어 모의 시험: LCD 1개 구성 35개 중 35개, LCD 3개 구성 18개 중 18개 통과.
2. 윈도우 전용 코드: 문서 폴더를 구함, 가상 보드 파일을 찾음, 같은 포트에 두 번째 서버가 붙지 못함(`WinError 10048`).
3. 빌드한 프로그램의 자동 점검. 프로그램이 자기 창 안의 화면을 직접 조작한다: 화면이 뜨고 가상 보드의 값이 차트에 들어옴 → `sp 60` 전송 → 운전 단추 → 확인 창이 뜸 → 확인 → 운전 상태 → 정지 단추 → 정지 상태.
4. 조용한 설치(지금 사용자용) → 시작 메뉴 바로 가기와 등록 정보(이름, 버전 1.5, 게시자) 확인 → **설치한 프로그램으로 같은 자동 점검** → 조용한 제거 → 프로그램과 바로 가기가 남지 않음.
5. 한국어 설치(`/LANG=ko`, 바탕화면 아이콘 포함) → 시작 메뉴와 바탕화면에 `밴드 히터 PID 기록` 바로 가기가 생김 → 제거 뒤 남지 않음.

## 알려진 제한

- 코드 서명이 없다. SmartScreen 경고가 뜨고, 백신에 따라서는 서명 없는 프로그램을 막거나 검사하느라 첫 실행이 느릴 수 있다.
- 알림 센터 알림(안정, 프로그램 종료, 경보, 연결 끊김)은 맥에서만 된다. 윈도우에서는 화면의 표시와 경보음, 이벤트 기록으로만 알린다.
- 자동 업데이트가 없다.
- 온도 프로그램 운전과 PC 경보는 PC와 이 프로그램이 켜져 있을 때만 동작한다. PC나 프로그램이 꺼지면 보드는 마지막 목표를 유지하고, 보호는 펌웨어와 하드웨어(과열 차단, 안전 릴레이, 서모스탯)에만 남는다.
- 펌웨어를 보드에 올리는 도구는 들어 있지 않다. 펌웨어는 아두이노 IDE나 avrdude로 올린다.

## 문제가 생기면

| 증상 | 볼 것 |
|---|---|
| "Windows의 PC 보호" 창이 뜬다 | 서명 없는 파일이라 그렇다. `추가 정보` → `실행` |
| 창이 하얗거나 비어 있다 | WebView2 런타임이 없거나 깨진 경우일 수 있다. Microsoft의 WebView2 페이지에서 Evergreen 런타임을 설치한다 |
| "보드를 찾는 중입니다 (USB를 연결하세요)"에서 멈춘다 | 장치 관리자의 "포트(COM & LPT)"에 보드가 보이는지 본다. 안 보이면 USB-시리얼 드라이버를 설치하거나 케이블을 바꾼다(충전 전용 케이블은 안 된다). 보이면 왼쪽 패널에서 그 COM 포트를 직접 고른다 |
| "다른 프로그램이 사용 중"이라고 나온다 | 아두이노 IDE의 시리얼 모니터나 다른 터미널 프로그램을 닫는다. 이 프로그램을 두 번 켠 경우에도 나온다 |
| 켜자마자 히터가 꺼졌다 | 포트를 열 때 나노가 리셋되는 것이다. 프로그램을 먼저 켜고 운전을 시작한다 |
| `연습 모드` 단추가 없다 | 가상 보드 파일이 없는 빌드다. 이 릴리스의 설치 파일에는 들어 있다 |
| 기록이 어디 있는지 모르겠다 | 왼쪽 패널의 `기록 폴더`를 누른다. 화면 아래에 지금 쓰는 파일의 경로가 보인다 |

그래도 안 되면 [이슈](https://github.com/jongsu-king/band-heater-pid/issues)에 윈도우 버전, 증상, 기록 폴더의 `_events.txt`와 `_raw.log`를 붙여 올린다.

## 받은 파일 확인

`SHA256SUMS.txt`의 값과 받은 파일의 해시가 같아야 한다. 값은 위 "받을 파일" 표에도 있다.

```powershell
Get-FileHash .\Band-Heater-Logger-1.5-windows-x64-setup.exe -Algorithm SHA256
```

```bat
certutil -hashfile Band-Heater-Logger-1.5-windows-x64-setup.exe SHA256
```

맥이나 리눅스에서는 두 파일을 같은 폴더에 두고 `shasum -a 256 -c SHA256SUMS.txt`를 실행한다.

## 빌드 정보

{{BUILD_KO}}

만드는 순서는 저장소의 `build_windows.bat`에 있고, GitHub Actions의 `Windows installer` 워크플로(`.github/workflows/windows-installer.yml`)가 그 파일을 그대로 실행한다.

1. `g++ -std=c++17 -w -static`으로 가상 보드 `tools/sim/sim_bin.exe`를 컴파일한다. 정적 링크라 컴파일러의 DLL이 필요 없다.
2. PyInstaller가 `packaging/heater_app.spec`으로 `dist/HeaterLog/`를 만든다. 콘솔 창이 뜨지 않는 폴더 빌드이고, tkinter, numpy, matplotlib, PIL은 뺐다.
3. Inno Setup 6이 `packaging/windows/installer.iss`로 설치 파일을 만든다. 압축은 LZMA2 최대, 설치 프로그램 자체는 32비트이고 프로그램은 64비트로 설치한다.
4. 워크플로가 위 "확인한 것"의 시험을 하고, 해시와 이 표의 값을 적는다.

같은 소스로 다시 빌드해도 파일의 해시는 달라진다(빌드 시각 등이 들어감).

# English

First Windows installer for the PC logger of the band heater PID controller, version 1.5. The program is the same as 1.5 in the source; what is new is everything needed to install and run it on Windows.

**Scope of what was checked.** The installer was built on a GitHub Actions Windows runner, where it was installed, self-tested with the virtual board, and uninstalled. Nobody has clicked through the installer on a real Windows PC yet, and it has not been tried with the real board on a COM port. See "What was and was not checked" below.

There is no macOS application in this release. On a Mac, build it from the source with `packaging/build_mac.sh` or run `uv run heater_app.py`.

## Requirements

| Item | Details |
|---|---|
| Operating system | Windows 10 or 11, 64-bit. The installer is for x64. On Windows 11 for ARM the installer is allowed to run under x64 emulation, but that was not tried |
| Window component | Microsoft Edge WebView2 Runtime. Part of Windows 11 and of up-to-date Windows 10. If it is missing, the installer says so at the end and can open the Microsoft download page |
| Python | Not needed. Python 3.12 and the packages are inside the install folder |
| Administrator rights | Not needed for the default per-user install. Needed if you choose "all users" |
| Disk | The size of the installed folder under "Build details". Records are stored separately in the Documents folder |
| Board connection | The Arduino Nano's USB. It must show up as a COM port under "Ports (COM & LPT)" in Device Manager. If it does not, install the driver for the board's USB-serial chip (FTDI, CH340, ...) |
| Firmware | The firmware in this repository. With v1.4 or later, program runs move the setpoint with `spt`, which does not write the EEPROM. Older firmware gets `sp`, which stores every change on the board |
| Internet | Not needed to install or run. The program's code does not contact any outside server |

## Installing

The sequence of pages follows from the settings in `packaging/windows/installer.iss`. The automated tests only used silent installs.

1. Download `Band-Heater-Logger-1.5-windows-x64-setup.exe`. To check the download, see "Checking the download".
2. Double-click it. The file is not code-signed, so "Windows protected your PC" (SmartScreen) appears. Choose `More info`, then `Run anyway`.
3. Choose who to install for. "Current user" (recommended) needs no administrator rights. "All users" asks for them.
4. Accept the licence (MIT).
5. Choose the folder. The default is `C:\Users\<user>\AppData\Local\Programs\Band Heater PID Logger` for the current user, or `C:\Program Files\Band Heater PID Logger` for all users.
6. Choose whether to create a desktop icon. Off by default.
7. Click `Install`. Leave "Launch" ticked and click `Finish` to start the program.

The installer follows the Windows display language: Korean on Korean Windows, English otherwise.

## What gets installed

| What | Where |
|---|---|
| Program | `HeaterLog.exe` and the `_internal` folder (Python runtime, pywebview, pyserial, the page `heater_log.html`, the virtual board `sim\sim_bin.exe`) in the install folder. Full list in `BUILD-INFO.txt` |
| Start menu shortcut | `Band Heater PID Logger`, or `밴드 히터 PID 기록` when installed in Korean |
| Desktop shortcut | Only if chosen; same name |
| Uninstaller | `unins000.exe` in the install folder. Listed as `Band Heater PID Logger` in Settings → Apps |
| Registration | `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\{AED7B226-0390-4D06-9414-BBF97850FE7D}_is1` for the current user, the same path under `HKLM` for all users |

No services, start-up entries, file associations, firewall rules or drivers are installed, and no environment variables are changed.

## First run

1. Start the program first. Opening the port resets the Nano (normal Arduino behaviour), so starting the program during a run turns the heater off. Start the run after the program is up.
2. Plug in the board. The program finds the port itself: it prefers ports whose USB vendor ID is FTDI (0403), CH340 (1A86), CP210x (10C4), Arduino (2341, 2A03) or Prolific (067B), at 115200 baud. With several ports, pick one from the port list in the left panel.
3. Once connected, the line the board sends every second goes to the chart and to the files. Every 3 s the program sends `show` to read the state and settings; `show` does not write the EEPROM.
4. Without a board, click `Practice mode` in the left panel. A virtual board (the firmware compiled as-is for the PC) runs at 30× speed. No real heater is switched. Its temperature curve comes from an arbitrary thermal model, not from the real heater.
5. The language (Korean or English) is chosen from the toolbar. It starts in Korean.

The window opens at 1280 × 880 and cannot be made smaller than 1000 × 700. The page is served only on this computer, at `127.0.0.1` port 8765 (the next ports up to 8784 if that one is taken). It cannot be reached from another computer, and requests that send commands are accepted only with a token that is new on every start. While the program is running it keeps the PC from going to sleep; it does not keep the display on.

The features (toolbar, chart, statistics, response, fit, model, analysis, temperature program, PC alarms, stability check, record list, report, settings, shortcuts) are listed in the [README](https://github.com/jongsu-king/band-heater-pid/blob/main/README.en.md#logger).

## Record files

Records go to `밴드히터_기록` in the Documents folder. The location of Documents is asked from Windows, so if it has been moved to OneDrive the folder is created there. `Record folder` in the left panel opens it in Explorer. Practice-mode records go to the `연습` subfolder.

Each record has four files whose names start with `heater_date_time_name`.

| File | Contents |
|---|---|
| `.csv` | One row per second. Columns: `time, elapsed_s, PV_degC, SP_degC, OUT_pct, T1_degC, T2_degC, T3_degC, T4_degC, mode` |
| `_events.txt` | Run, stop, alarms, setting changes, commands sent, markers |
| `_raw.log` | Every line from the board, with the time it arrived |
| `_meta.json` | Experiment name, sample, notes, channel names, firmware version, PID settings at the start, column descriptions |

Saving from the screen adds `_stats.tsv` (range statistics), `_part_*.csv` (a range only), `_graph_*.png` (image) and `_report_*.html` (report) with the same name stem. Program steps, alarm limits and the language are kept in `설정.json` in the record folder. A record with no data rows and no markers is deleted when it is closed.

## Uninstalling, reinstalling, new versions

- Uninstall: Settings → Apps → Installed apps → `Band Heater PID Logger`. The program folder, shortcuts and registration are removed. **The record folder (`밴드히터_기록`) is not touched.**
- Reinstall: run the same installer again; it installs over the same place.
- New version: a newer installer is meant to install over the old one (it empties the old `_internal` folder first). This is the first release, so an upgrade install has not been tested.
- There is no automatic update. New versions appear in this repository's releases.

## What changed for Windows

The program's features are those of 1.5. These changes make it behave correctly on Windows; macOS and Linux behave as before.

| Part | Change |
|---|---|
| Virtual board (`tools/sim/sim.cpp`) | On Windows it reads only what is waiting in the standard-input pipe (`PeekNamedPipe`). Because `Sleep` can overrun by up to about 15 ms, it sleeps only as far as it is ahead of real time, which keeps the speed factor right |
| Starting the virtual board (`heater_log.py`) | On Windows it looks for `sim_bin.exe` and starts it without a console window |
| Record folder | On Windows the Documents folder is asked from the system (`SHGetFolderPathW`), for PCs where it has been moved, for example to OneDrive |
| Sleep prevention | `SetThreadExecutionState`, the counterpart of `caffeinate` on macOS |
| Starting it twice | On Windows the page server could attach to a port that is already in use (`SO_REUSEADDR` works differently), so that option is off there and the next port is used |
| Port in use | The error Windows gives when another program holds the COM port (`PermissionError`) is now also shown as "in use by another program (close the Arduino serial monitor)" |
| Bundle (`packaging/heater_app.spec`) | On Windows it builds a folder and writes the version into the exe's file properties; the installer script reads it from there |
| Build (`build_windows.bat`) | Compiles the virtual board, runs PyInstaller and then Inno Setup |

## Known limitations

- Not code-signed. SmartScreen warns, and some antivirus products block unsigned programs or slow the first start while scanning.
- Notification-centre alerts (stable, program finished, alarm, connection lost) are macOS only. On Windows these are shown on screen, by the alarm sound and in the event log.
- No automatic update.
- Temperature programs and PC alarms work only while the PC and this program are running. If either stops, the board keeps the last setpoint and protection is left to the firmware and hardware (over-temperature cut-off, safety relay, thermostat).
- No tool for uploading the firmware is included. Upload it with the Arduino IDE or avrdude.

## Troubleshooting

| Symptom | What to check |
|---|---|
| "Windows protected your PC" | The file is unsigned. `More info` → `Run anyway` |
| The window is white or empty | The WebView2 Runtime may be missing or broken. Install the Evergreen runtime from Microsoft's WebView2 page |
| It stays at "Looking for the board (plug in the USB cable)" | See whether the board appears under "Ports (COM & LPT)" in Device Manager. If not, install the USB-serial driver or change the cable (charge-only cables do not work). If it does, pick that COM port in the left panel |
| "in use by another program" | Close the Arduino IDE serial monitor or any other terminal program. It also appears if this program is started twice |
| The heater went off when the program started | Opening the port resets the Nano. Start the program first, then the run |
| There is no `Practice mode` button | The build has no virtual board. The installer in this release includes it |
| Where are the records? | Click `Record folder` in the left panel. The path of the current file is shown at the bottom of the window |

If that does not help, open an [issue](https://github.com/jongsu-king/band-heater-pid/issues) with the Windows version, what happened, and the `_events.txt` and `_raw.log` of the record.

## Build details

{{BUILD_EN}}

The steps are in `build_windows.bat`; the `Windows installer` workflow (`.github/workflows/windows-installer.yml`) runs that file as it is.

1. `g++ -std=c++17 -w -static` compiles the virtual board `tools/sim/sim_bin.exe`. It is linked statically, so no compiler DLLs are needed.
2. PyInstaller builds `dist/HeaterLog/` from `packaging/heater_app.spec`: a folder build without a console window, with tkinter, numpy, matplotlib and PIL left out.
3. Inno Setup 6 builds the installer from `packaging/windows/installer.iss`: LZMA2 maximum compression; the setup program itself is 32-bit and installs the program as 64-bit.
4. The workflow runs the checks listed above and records the hash and the values in this table.

Rebuilding from the same source gives a file with a different hash (build times are embedded).
